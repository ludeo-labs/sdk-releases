◆ maxConcurrentWrites

uint32_t LudeoSessionOpenRoomParams::maxConcurrentWrites

Maximum number of concurrent in-flight object writes allowed before a game thread blocks.

Only meaningful when threadSafe == LUDEO_TRUE. Ignored in single-threaded mode. Only read when apiVersion >= 2.

When 0, the SDK uses the default limit (1024), which is sufficient for most games.

Each ludeo_DataWriter_LeaveObject and ludeo_DataWriter_DestroyObject call counts as one in-flight write until the SDK has finished processing it. If this limit is reached, the calling game thread will block until a slot becomes available. Increase this value if your game writes to many objects simultaneously from many threads in a single frame (e.g. 200+ objects across 8 threads at once).

◆ threadSafe

LudeoBool LudeoSessionOpenRoomParams::threadSafe

Set to LUDEO_TRUE to opt into a thread-safe DataWriter.

Default: LUDEO_FALSE. Only read when apiVersion >= 2.

When LUDEO_TRUE, the following functions are fully concurrent-safe and may be called simultaneously from multiple game threads:

  • ludeo_DataWriter_EnterObject / ludeo_DataWriter_LeaveObject
  • ludeo_DataWriter_EnterComponent / ludeo_DataWriter_LeaveComponent
  • All ludeo_DataWriter_SetXxx functions
  • ludeo_DataWriter_DestroyObject
  • ludeo_DataWriter_SendAction

ludeo_DataWriter_CreateObject is also thread-safe while by nature can not be called concurrently.

The following functions are not designed for concurrent use and must only be called from the main thread (same restriction as in single-threaded mode):

  • ludeo_DataWriter_SetCurrent
  • ludeo_DataWriter_SetSendSettings
  • ludeo_DataWriter_SaveStorage

ludeo_DataWriter_EnterObjectLate is not supported with a thread-safe DataWriter. Calling it will log an error and return LUDEO_FALSE.
